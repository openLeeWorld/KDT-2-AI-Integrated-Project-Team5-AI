# Food Master 적재 규칙

## 목적

이 문서는 `전국통합식품영양성분정보_원재료성식품_표준데이터` CSV 또는 Parquet에서 서비스가 사용할
Food Master를 만드는 방법을 설명한다.

Food Master는 상품이나 원천 데이터의 한 행을 그대로 저장하는 테이블이 아니다. 여러 상품·레시피·
향후 영양 정보가 함께 가리킬 수 있는 **일반 식품 단위**를 저장한다.

```text
원천 식품 데이터
   │
   ├─ 식품 identity 선택
   ├─ 이름·코드 충돌 해소
   └─ 필요한 하위 식품만 추가
   │
   ▼
food_source 1행 + food 여러 행
```

## Food로 만드는 기준

### 1. 대표식품은 기본 Food다

대표식품은 기본적으로 하나의 Food가 된다.

```text
대표식품코드 = 02001
대표식품명   = 감자
중분류        = 수미 / 대지 / …

→ Food = 감자
→ basis_level = REPRESENTATIVE
```

감자의 품종, 생것·삶은것 같은 조리 상태, 원산지, 생산월, 영양성분은 감자라는 identity를 바꾸지
않는다. 이런 값은 `food`에 넣지 않으며, 나중에 원천 관측 데이터로 연결한다.

### 2. 하위 분류는 실제로 다른 식품일 때만 추가한다

중분류라고 해서 모두 Food가 되는 것은 아니다. 아래 두 경우에만 별도 Food를 만든다.

#### 독립 식품

중분류 자체가 구매·조리·검색에서 구별되는 식품일 때다. 대표식품을 parent로 둔다.

```text
호박 → 애호박
파   → 대파
토마토 → 방울토마토
```

예를 들어 `애호박` Food의 parent는 `호박`이며, basis는 원천 중분류 `0619805`다.

#### 결합 식품

대표식품명과 중분류명을 함께 써야 실제 식품명이 되는 경우다. 이때도 대표식품을 parent로 둔다.

```text
전분 + 고구마 → 고구마 전분
당면 + 고구마 → 고구마 당면
```

Food Master에는 소면·우동·대파·애호박·방울토마토 같은 독립 식품과 감자 전분·고구마 전분·
옥수수 전분·고구마 당면 같은 결합 식품이 포함되어 있다.

### 3. 크기 차이는 Food를 늘리지 않는다

`기름가자미(20cm미만)`, `기름가자미(25-29cm)`처럼 크기만 다른 원천 중분류는 `기름가자미` 한
Food로 묶는다. 크기 값은 Food identity가 아니라 향후 관측 또는 속성으로 연결할 값이다.

같은 방식으로 갈치의 크기 구간은 `갈치`, 보구치의 크기 구간은 `보구치` 하나로 만든다. 어떤 원천
중분류 코드들이 하나의 Food에 포함되는지는 Food 생성 근거로 보존한다.

## 코드와 이름이 충돌할 때

공식 대표식품 코드 하나가 서로 다른 식품 이름을 가리키는 경우가 있다. 이때 코드만으로 Food를
식별하면 서로 다른 식품을 잘못 합칠 수 있다.

`source_identity_key`는 이 문제를 해결하는 안정적인 원천 식별자다.

```text
K-FIND:{대분류코드}:{해결된 대표식품코드}:{공백을 제거한 해결된 이름}
```

예를 들어 원천 코드 `06101`은 다음 두 Food를 만든다.

| 원천 코드 | 원천 이름 | 저장하는 basis code | source_identity_key |
| --- | --- | --- | --- |
| `06101` | 상추 | `06101-01` | `K-FIND:06:06101-01:상추` |
| `06101` | 생강 | `06101-02` | `K-FIND:06:06101-02:생강` |

반대로 같은 식품의 표기 차이는 하나로 합친다.

```text
맵쌀 국수 + 멥쌀 국수
→ Food = 멥쌀 국수
→ source_identity_key = K-FIND:01:01010:멥쌀국수
```

충돌·표기 병합 규칙이 없는 원천 코드는 자동으로 Food를 만들지 않고 검토 대상으로 남긴다.

## 데이터 품질 원칙

- 원천 코드 충돌은 이름만 보고 임의로 합치지 않는다.
- 판매명에 Food 이름이 없으면, 검토된 동의어 또는 명시적인 상품 카테고리 근거가 있을 때만 연결한다.
- 상품의 손질·절단·크기·품종·원산지는 Food를 새로 만들지 않고 상품과 Food의 관계에 남긴다.
- 한 상품 안에 여러 식품이 섞였거나 가공 여부가 불명확하면 하나의 Food로 억지로 연결하지 않고 보류한다.
