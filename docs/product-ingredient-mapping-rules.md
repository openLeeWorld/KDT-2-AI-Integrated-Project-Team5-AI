# 상품 Variant와 Ingredient Master 연결 규칙

## 목적

상품은 판매 단위이고 Ingredient Master는 재료 단위다. 따라서 상품명만 비슷하다는 이유로 둘을 바로
같다고 볼 수 없다. Ingredient Master는 신선식품 도메인의 재료 축만 관리하며, 양념·조리·밀키트·완제품
같은 푸드 상품과 메뉴·상황 같은 요리 의도는 Product 또는 서비스 태그 레이어에서 관리한다.

Ingredient Master의 물리 저장소는 `ingredient_master.ingredient`이며, 연결 기본키는
`ingredient_id`다. 결과는 자동 확정값이 아니라, 근거와 함께 남기는 Ingredient 후보이다.

```text
상품 Variant
   │
   ├─ 단일 원물인지 확인
   ├─ Ingredient 후보 검색
   ├─ 가장 구체적인 재료 후보 선택
   └─ 후보·근거·보류 사유 기록
   │
   ▼
Product Variant → Ingredient 후보
```

## 1. 상품 페이지가 아니라 Variant를 연결한다

한 상품 페이지에는 서로 다른 식품 옵션이 섞일 수 있다. 예를 들어 한 페이지에서 목살과 삼겹살을
함께 판매하면 페이지 이름만으로 하나의 Ingredient를 고를 수 없다.

- 옵션이 하나이거나 모든 옵션이 같은 Ingredient인 경우: Variant 단위 후보를 생성한다.
- 옵션이 분리되지 않은 경우: `REVIEW`로 보류한다.
- 서로 다른 원물이 섞인 상품인 경우: 단일 Ingredient에 연결하지 않고 구성 원물별 연결을 별도로 검토한다.

## 2. 먼저 매핑 범위를 판정한다

현재 자동 후보 생성 대상은 단일 재료 성격이 분명한 상품이다. 냉장·냉동은 보관 속성이므로 그것만으로
대상에서 제외하지 않는다.

| 판정 | 예시 | 처리 |
| --- | --- | --- |
| `TARGET` | 감자, 애호박, 생닭, 삼겹살, 생연어, 우유 | Ingredient 후보 생성 |
| `REVIEW` | 혼합 농산물, 원물 여부가 불명확한 가공품, 옵션 미분리 상품 | 자동 연결하지 않음 |
| `DEFER` | 양념육·훈제육·조리 완료 식품·밀키트·완제품 | 푸드 상품 또는 상품 원재료 구성 모델에서 별도 처리 |
| `OUT_OF_SCOPE` | 식품 여부나 카테고리를 확인할 수 없는 상품 | 연결하지 않음 |

`TARGET`이라고 해서 자동 확정되는 것은 아니다. 후보를 만든다는 뜻이다.

## 3. 후보를 만드는 근거

### Ingredient 표준명 일치

상품명에서 Ingredient의 표준명이 직접 확인되면 후보로 만든다.

```text
친환경 애호박 1개 → 애호박
방울토마토 500g → 방울토마토
```

### 검토된 판매명 동의어

판매명과 원천 표준명이 다를 때는 검토된 동의어만 사용한다. 임의의 유사어 추론이나 형태소 유사도
검색으로 Ingredient를 확정하지 않는다.

```text
새송이버섯 → 큰느타리버섯(새송이버섯)
파프리카 → 파프리카(착색단고추)
닭가슴살 → 닭고기 + 부위=가슴(껍질 제거)
삼겹살 → 돼지고기 + 부위=삼겹살
```

동의어가 상품의 상태나 부위를 함께 뜻하면 Ingredient를 바꾸지 않고 상품-Ingredient 관계의 속성으로 남긴다.

### 카테고리는 보조 근거다

카테고리는 후보 범위를 좁히거나 같은 이름의 Ingredient branch를 고르는 데만 사용한다. 카테고리만으로
Ingredient를 새로 만들거나, 상품명에 없는 재료를 확정하지 않는다.

```text
채소 > 근채류 > 고구마 / 호박고구마
→ 채소류 branch의 고구마를 우선

과일/견과 > 국산과일 > 토마토 / 대추방울토마토
→ 방울토마토를 후보로 선택
```

예외적으로 `한우/육우 > 육우`, `수입육 > 수입산 돼지고기`처럼 동물 종류와 원산지를 명시하는 축산
카테고리는 상품명에 부위만 있어도 종을 정하는 근거가 된다. 이 경우에도 부위는 Ingredient가 아니라 관계
속성으로 남긴다.

## 4. 더 구체적인 Ingredient를 우선한다

상품명에 parent Ingredient와 child Ingredient가 함께 잡히면 child Ingredient가 우선한다.

```text
호박 + 애호박 후보 → 애호박
토마토 + 방울토마토 후보 → 방울토마토
```

한 Ingredient 안의 품종·크기·손질·절단·원산지·도정 형태·냉장/냉동은 별도 Ingredient를 만들지 않는다.

| 상품 표현 | Ingredient | 관계 속성 예시 |
| --- | --- | --- |
| 대추방울토마토 | 방울토마토 | 품종=대추 |
| 호박고구마 | 고구마 | 판매 변형=호박고구마 |
| 깐 감자 | 감자 | 박피 상태=깐 |
| 한돈 삼겹살 | 돼지고기 | 원산지=국내산, 부위=삼겹살 |

## 5. 억지로 하나를 고르지 않는다

다음 상태는 정상적인 결과이며, 사람이 검토하거나 다른 데이터가 필요하다는 뜻이다.

| 상태 | 의미 |
| --- | --- |
| `CANDIDATE` | 근거가 있는 단일 Ingredient 후보 |
| `AMBIGUOUS` | 서로 다른 Ingredient 후보가 둘 이상 |
| `UNMAPPED` | 현재 Ingredient Master와 검토된 동의어로 연결할 수 없음 |
| `REVIEW` | 옵션 분리·혼합 여부·가공 상태 등을 먼저 확인해야 함 |
| `DEFER` | 재료 연결보다 푸드 상품·상품 원재료 구성 모델이 적합함 |
| `OUT_OF_SCOPE` | 현재 대상 밖 |

예를 들어 샐러드·나베용 채소처럼 여러 원물이 들어간 상품은 `REVIEW`다. 닭가슴살이라는 말이 있어도
양념·소스·훈제·조리된 완제품·밀키트이면 `DEFER`로 둔다. 메뉴·상황·인분은 Ingredient가 아니라
요리 태그 또는 상품 속성으로 남긴다.

## 6. 저장하는 결과

각 후보에는 최소한 아래 정보를 함께 남긴다.

| 항목 | 의미 |
| --- | --- |
| `variant_id` | 판매 Variant 식별자 |
| `ingredient_id` | 연결 후보 Ingredient의 물리 식별자 |
| `mapping_status` | 후보·보류·미연결 상태 |
| `matched_term` | 상품명 또는 동의어 중 실제 일치한 표현 |
| `match_method` | 표준명 일치인지, 검토된 동의어인지 |
| `attributes` | 부위·품종·크기·보관 상태 등 Ingredient 자체가 아닌 상품 관계 속성 |
| `reason` | 상태 또는 보류 사유 |

이 기록이 있어야 나중에 Ingredient Master가 바뀌거나 동의어가 추가되었을 때, 어떤 근거로 연결되었는지
재검토할 수 있다.
