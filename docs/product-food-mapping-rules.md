# 상품과 Food Master 연결 규칙

## 목적

상품은 판매 단위이고 Food Master는 일반 식품 단위다. 따라서 상품명만 비슷하다는 이유로 둘을 바로
같다고 볼 수 없다.

이 문서는 상품 Variant 하나가 어떤 Food에 연결될 수 있는지 판단하는 기준을 설명한다. 결과는 자동
확정값이 아니라, 근거와 함께 남기는 Food 후보이다.

```text
상품 Variant
   │
   ├─ 단일 원물인지 확인
   ├─ Food 후보 검색
   ├─ 가장 구체적인 후보 선택
   └─ 후보·근거·보류 사유 기록
   │
   ▼
Product Variant → Food 후보
```

## 1. 상품 페이지가 아니라 Variant를 연결한다

한 상품 페이지에는 서로 다른 식품 옵션이 섞일 수 있다. 예를 들어 한 페이지에서 목살과 삼겹살을
함께 판매하면 페이지 이름만으로 하나의 Food를 고를 수 없다.

- 옵션이 하나이거나 모든 옵션이 같은 Food인 경우: Variant 단위 후보를 생성한다.
- 옵션이 분리되지 않은 경우: `REVIEW`로 보류한다.
- 서로 다른 원물이 섞인 상품인 경우: 단일 Food에 연결하지 않고 구성 원물별 연결을 별도로 검토한다.

## 2. 먼저 매핑 범위를 판정한다

현재 자동 후보 생성 대상은 단일 원물 성격이 분명한 상품이다.

| 판정 | 예시 | 처리 |
| --- | --- | --- |
| `TARGET` | 감자, 애호박, 생닭, 삼겹살, 생연어, 우유 | Food 후보 생성 |
| `REVIEW` | 손질·냉동·혼합 농산물, 가공란, 수산 가공품, 옵션 미분리 상품 | 자동 연결하지 않음 |
| `DEFER` | 소스·양념·조리법이 상품 identity인 가공식품, 밀키트, 완제품 | Product 또는 Ingredient 모델에서 별도 처리 |
| `OUT_OF_SCOPE` | 식품 여부나 카테고리를 확인할 수 없는 상품 | 연결하지 않음 |

`TARGET`이라고 해서 자동 확정되는 것은 아니다. 후보를 만든다는 뜻이다.

## 3. 후보를 만드는 근거

### Food 표준명 일치

상품명에서 Food의 표준명이 직접 확인되면 후보로 만든다.

```text
친환경 애호박 1개 → 애호박
방울토마토 500g → 방울토마토
```

### 검토된 판매명 동의어

판매명과 원천 표준명이 다를 때는 검토된 동의어만 사용한다. 임의의 유사어 추론이나 형태소 유사도
검색으로 Food를 확정하지 않는다.

```text
새송이버섯 → 큰느타리버섯(새송이버섯)
파프리카 → 파프리카(착색단고추)
닭가슴살 → 닭고기 + 부위=가슴(껍질 제거)
삼겹살 → 돼지고기 + 부위=삼겹살
```

동의어가 상품의 상태나 부위를 함께 뜻하면 Food를 바꾸지 않고 상품-Food 관계의 속성으로 남긴다.

### 카테고리는 보조 근거다

카테고리는 후보 범위를 좁히거나 같은 이름의 Food branch를 고르는 데만 사용한다. 카테고리만으로
Food를 새로 만들거나, 상품명에 없는 식품을 확정하지 않는다.

```text
채소 > 근채류 > 고구마 / 호박고구마
→ 채소류 branch의 고구마를 우선

과일/견과 > 국산과일 > 토마토 / 대추방울토마토
→ 방울토마토를 후보로 선택
```

예외적으로 `한우/육우 > 육우`, `수입육 > 수입산 돼지고기`처럼 동물 종류와 원산지를 명시하는 축산
카테고리는 상품명에 부위만 있어도 종을 정하는 근거가 된다. 이 경우에도 부위는 Food가 아니라 관계
속성으로 남긴다.

## 4. 더 구체적인 Food를 우선한다

상품명에 parent Food와 child Food가 함께 잡히면 child Food가 우선한다.

```text
호박 + 애호박 후보 → 애호박
토마토 + 방울토마토 후보 → 방울토마토
```

한 Food 안의 품종·크기·손질·절단·원산지·도정 형태는 별도 Food를 만들지 않는다.

| 상품 표현 | Food | 관계 속성 예시 |
| --- | --- | --- |
| 대추방울토마토 | 방울토마토 | 품종=대추 |
| 호박고구마 | 고구마 | 판매 변형=호박고구마 |
| 깐 감자 | 감자 | 박피 상태=깐 |
| 한돈 삼겹살 | 돼지고기 | 원산지=국내산, 부위=삼겹살 |

## 5. 억지로 하나를 고르지 않는다

다음 상태는 정상적인 결과이며, 사람이 검토하거나 다른 데이터가 필요하다는 뜻이다.

| 상태 | 의미 |
| --- | --- |
| `CANDIDATE` | 근거가 있는 단일 Food 후보 |
| `AMBIGUOUS` | 서로 다른 Food 후보가 둘 이상 |
| `UNMAPPED` | 현재 Food Master와 검토된 동의어로 연결할 수 없음 |
| `REVIEW` | 옵션 분리·혼합 여부·가공 상태 등을 먼저 확인해야 함 |
| `DEFER` | 원물 Food 연결보다 상품·원재료 모델이 적합함 |
| `OUT_OF_SCOPE` | 현재 대상 밖 |

예를 들어 샐러드·나베용 채소처럼 여러 원물이 들어간 상품은 `REVIEW`다. 닭가슴살이라는 말이 있어도
양념·소스·조리된 완제품이면 `DEFER`로 둔다.

## 6. 저장하는 결과

각 후보에는 최소한 아래 정보를 함께 남긴다.

| 항목 | 의미 |
| --- | --- |
| `variant_id` | 판매 Variant 식별자 |
| `food_id` | 연결 후보 Food 식별자 |
| `mapping_status` | 후보·보류·미연결 상태 |
| `matched_term` | 상품명 또는 동의어 중 실제 일치한 표현 |
| `match_method` | 표준명 일치인지, 검토된 동의어인지 |
| `attributes` | 부위·품종·크기 등 Food 자체가 아닌 상품 관계 속성 |
| `reason` | 상태 또는 보류 사유 |

이 기록이 있어야 나중에 Food Master가 바뀌거나 동의어가 추가되었을 때, 어떤 근거로 연결되었는지
재검토할 수 있다.
